Capacity
Selected artifact inventories plus full authenticated DMA parent inventories share an explicit 1,073,741,824-byte budget. Manifest bytes count. Each parent authentication counts again, including a parent also supplied as a selected artifact. Inventory accounting is checked before loading its members. Each inventory also has the 1 GiB bound; source members remain at most 64 MiB, source manifests 2 MiB, inventories 2048 members plus the manifest, module graphs 768 modules and translation lists 512 members. The pinned site baseline retains its 256 MiB bound. Each game-package/1 retains the independent 256 MiB and 1024-member ceiling, including shared dependencies. The bundle writer is bounded to 6 GiB for site/, replacements/, retained originals and provenance parents. Existing output-member, file-count, evidence-file, input-JSON and deadline bounds remain. A large accepted inventory can still fail another explicit bound. Memory use scales with source bytes; a 1 GiB input budget is not an RSS or performance guarantee.

Authentication and evidence
Build accepts 1–8 games with explicit labels, closed artifact directory, manifest and compiler manifest SHA-256 pins, machine entry, ROM hash, exact board policy and independently supported gameplay mode. No title, path or ROM-hash lookup selects hardware behavior. Original source.nes, compiled.mjs, runtime.mjs, translation modules and NOTICE.txt remain mandatory. Static local module checks, generated CPU/interpreter guards, source rereads, hash/length checks, duplicate JSON rejection and symlink/hardlink protections remain. Hashes do not authenticate the truth of assertions.

An independent hashed evidence file has exactly:

A reviewer must create this from independently reviewed real evidence. The builder reads and hashes sources, never manufactures a production receipt.

Board and persistence
Existing mapper 1/2/4 contracts are unchanged. MMC5 supports only ELROM/none/0 PRG RAM or EKROM/8k/8192 PRG RAM, CHR ROM only. Exact mapper_policy fields: board, prg_ram, revision, wiring, audio, startup, exram_blank_write, chr_latch. Required values are MMC5, CL, nes-disconnected, reset-defined-zero-other, zero and mode-latched-reject-unknown respectively. NTSC iNES, API 3, fetch-epoch-2, mmc5-1, submapper 0, mapper_controlled mirroring, supported ROM geometry, metadata and component hashes remain checked. Unsupported board/RAM/revision policies fail.

Nonbattery uses battery_hooks=none. Existing hooks must export/import an exact 8192-byte Uint8Array. Mapper 1/2/4 add-base-ram-v1 retains the exact existing accessor seam and preserves volatile RAM; unsupported machine seams still fail. MMC5 forbids accessor insertion and requires existing hooks when battery-backed. The versioned save identity includes ROM hash, mapping identity, mapper and exact RAM size. Restoration precedes ready/first frame. Checkpoints occur every 60 frames. Graceful reset/dispose pauses and flushes with a four-second bound before termination. Storage denial, quota, malformed saves and identity errors fail visibly. Abrupt termination can lose the last checkpoint interval. Saves remain device/origin local; stream receivers create no save worker.

Nested DMA, arbitrary wrappers and unknown future performance formats fail.

The derived compiler identity is recomputed with the producer's ordered compact ASCII JSON plus trailing newline, binding revision, parent manifest, tool source, dependency source and effective source. Launcher repair audit fields are validated but never executed. Original metadata must remain exactly equal after removing the two DMA additions. Compiler inventory membership and all current hashes must agree. The wrapper inherits original fields except the explicit producer fields. Closed parent inventory, source shape, changed/preserved lists and exact addition set are checked. Only the producer's known machine/runtime/compiled/bank/compiler-manifest/runtime-files changes may differ from the parent. The consumer never performs those changes.

Each concatenated gzip diff member is bounded, parsed and compared with both authenticated parent and derived text, including filenames, hunk coordinates, context and all unchanged gaps. Nothing is applied. Runtime, bundle, output and validation-input inventories are cross-checked. The generated machine graph must include the DMA, PPU and device modules. Producer tests remain historical scoped documents; their presence or passed flag does not satisfy independent completed_validation. Source-specialized engines, including all derived CPU/runtime/timing bytes, are copied unchanged. Final performance derivation is unknown and unsupported. No hardware, gameplay, FPS or publication readiness is inferred.
