# ROMJS static translation API 3
Import {createCPU,createBus,getPRG,getCHR,getTrainer,metadata,CPUError} from compiled.mjs. Copy and verify the complete manifest graph, including every bank module. Import real file URLs in Node; serve modules over HTTP in browsers. Production modules use no Node APIs, dependencies, eval, dynamic compilation or opcode interpreter. Migrate consumers and integrity pins deliberately; v1/v2 adapters are not implicitly compatible.

Strict ordinary iNES only; NES 2.0, VS/PlayChoice, ambiguous padding, extended RAM, unsupported wiring and trailing bytes are errors. NROM retains 16/32 KiB PRG, zero/8 KiB CHR, optional trainer and its 8 KiB compatibility RAM. UxROM retains explicit UNROM 64/128 KiB or UOROM 256 KiB policy, AND/no bus conflicts, startup bank and none/compat8k RAM. Each RMW write sees the current UxROM mapping. Fixed last bank, disconnected address masks, mapping identity and epoch checks remain.

Mapper 1 requires mmc1={wiring,revision,prg_ram,startup_control,startup_chr0,startup_chr1,startup_prg}. All startup registers are 0..31. They define a deterministic simulation, not power-up guarantees. Serial state starts empty and PPU address starts zero. wiring=standard connects ordinary MMC1 PRG/CHR bank outputs and optional none/8k PRG RAM; this includes SGROM-style 256 KiB PRG with CHR RAM and no PRG RAM. wiring=SNROM additionally connects CHR A16 to RAM /CE, requires 8 KiB PRG RAM and 8 KiB CHR ROM/RAM. wiring=fixed32 models SEROM/SHROM-style CPU A14 wiring, requires 32 KiB PRG, no PRG RAM and 16-128 KiB CHR ROM. Standard PRG sizes are powers of two from 16 through 256 KiB. CHR is 8 KiB RAM or powers of two from 8 through 128 KiB ROM. Geometry does not choose wiring. SOROM/SUROM/SXROM/SZROM, outer PRG banking, >8 KiB PRG RAM, flash, EEPROM, unusual clones and mixed CHR ROM/RAM are unsupported.

revision=MMC1B implements PRG bit4 RAM-disable; revision=MMC1A keeps RAM enabled except SNROM gating and implements bit4 bypass of fixed-bank A17 by PRG bit3. Other chip revisions are not silently guessed. The policy models the documented A/B behavioral classes, not analog revision differences.

Serial writes use bit0 LSB first. Only the fifth accepted write's A14/A13 choose the destination. Bit7 at ANY PRG address clears serial state and ORs control with 12, preserving CHR mode, mirroring and bank registers. Reset writes remain effective on consecutive cycles. All CPU writes record their cycles, including ignored serial writes and writes outside PRG: data writes immediately following any write are suppressed, including chains. This follows the documented digital consecutive-write model; the wiki describes the non-port first-write case as believed behavior. No analog bus contention is modeled. MMC1 has no bus conflicts.

All four PRG modes, both CHR modes and four CIRAM mirroring modes are implemented. Low disconnected address lines are masked by physical bank count. Serial progress, ignored/reset writes, PPU address changes and state restoration advance epochs. Console CPU reset preserves the mapper and serial state; vectors come from the CURRENT high window. Metadata vectors are explicitly startup vectors only. BRK/IRQ/NMI read live vector bytes.

createBus(io={read?,write?,peek?}) provides CPU read/peek/write, mapPRG, mapper state, snapshot/loadRAM, mapCHR, peekCHR, ppuRead/ppuWrite, setPPUAddress, getMirroring, mapNametable and loadCHR. Missing hardware/open-bus read handlers throw HARDWARE_UNIMPLEMENTED. Disabled installed RAM reads use those callbacks and writes are ignored. Absent RAM writes use io.write. Battery persistence is the integrator's responsibility. RAM initializes to zero; trainer initializes $7000-$71ff. CHR ROM writes have no memory effect. Copies returned by getters/snapshots do not mutate cartridge memory.

mapCHR accepts $0000-$1fff and returns a physical byte offset; it and peekCHR are pure. ppuRead/ppuWrite drive PPU address and access pattern memory. setPPUAddress accepts $0000-$3fff and MUST also be called for other real PPU bus address changes, including nametable fetches. SNROM RAM gating uses the currently driven PPU A12 and the selected CHR register. mapNametable maps $2000-$3eff to a CIRAM offset, folding $3000 mirrors; it is pure and does not contain nametable RAM. No PPU timing, renderer, APU, DMA or controllers are implemented. Four-screen NROM returns offsets up to 4095 for external RAM.

MMC1 CPU write signature is write(address,byte,absoluteCycle). The cycle is a nonnegative safe integer, REQUIRED for every CPU write. getCPUClock returns the next available CPU cycle. advanceCPUClock(t) advances idle/read time monotonically; use it to account for integration stalls. CPU instructions supply zero-based offsets: stores on final cycle; RMW old/new values on final two cycles; stack writes on their documented cycles. The CPU advances the bus clock by complete instruction/interrupt/reset cycles. s.cycles remains a user-adjustable reporting counter; changing it does NOT rewind cartridge time. Direct integration writes must use the same timeline; untimed writes fail. NROM/UxROM retain two-argument writes. Custom MMC1 wrappers MUST forward the third write argument and timing hooks. This is accurate write scheduling for the supported instructions, not a full dummy-read bus trace or DMA implementation.

getMapperState returns an identity-bound complete mapper snapshot (registers, partial serial bits/count, last write cycle, clock, PPU address, epoch and derived windows/RAM gate). loadMapperState validates all fields and derived values atomically, restores clock/serial/register/PPU state, and advances the current epoch instead of rolling it back. loadRAM and loadCHR validate exact array sizes. Restore CPU, RAM and mapper only between steps; CPU interrupt signal state is separate, so these APIs are not full-machine checkpoints. Hook truthfulness is an integration invariant, not a sandbox against malicious callbacks.

CPU getState/setState/step/run/reset/setIRQ/setNMI/requestNMI/getSignals preserve v2 semantics. Status bit5=1 and bit4=0. Initial SP=$fd, P=$24, cycles=7. reset subtracts three from SP, sets I, preserves registers/RAM/mapper, reads reset vector and costs seven cycles. step executes one instruction or interrupt entry. IRQ is level-sensitive; NMI latches rising edges; NMI wins. CLI/SEI/PLP sample prior I; RTI uses restored I; one handler instruction executes after entry. Interrupts are instruction-boundary approximations. Exceptions can leave partial stack/device state; discard or explicitly restore before resuming.

run defaults to 1000 steps, 100000 cycles, 1000 ms; maxima are 1000000 steps, 10000000 cycles, 5000 ms. Limits are checked between instructions (up to six-cycle overshoot). Synchronous callbacks must be bounded. Reentry is rejected.

All 151 official encodings are emitted as actual constant-operand JavaScript functions. Binary ADC/SBC ignore D, with official cycle totals, page/branch penalties, NMOS indirect-JMP wrap, zero-page/stack wrap and old/new RMW writes. For MMC1 each physical bank has low- and high-window modules; the at-most-two low-window crossing starts have statically emitted variants for each high bank. No full bank-pair duplication or runtime opcode decoding occurs. Mapping identity, physical offsets, epochs and source bytes are validated before EVERY translated instruction. RAM execution, mutable/changed code, unofficial opcodes and operands wrapping $ffff into RAM trap. Missing candidates trap; no fallback exists.

Fetch diagnostic revision: instruction peeks, instruction reads, missing-entry peeks and each reset/IRQ/NMI/BRK vector byte check mapping stability around callbacks. mapPRG itself is bracketed by epoch checks. Valid mapping changes, even ABA or no-op writes, throw MAPPING_CHANGED before interpreting a callback's offset/byte result. Stable incorrect offsets still throw BAD_MAPPING; stable changed source bytes still throw CODE_CHANGED; invalid state identities/fields remain BAD_MAPPING. Semantic writes are outside this fetch guard and may legitimately remap the next instruction, including on the final CPU cycle. Callbacks must not mutate mapper state during fetch.

scan_complete means enumeration only, not reachability, code/data classification or complete conversion. Compilation never runs ROM code. complete_conversion is always false. Manifest hashes cover all graph files; the manifest's hash is returned separately. The baseline source hash is supplied provenance, not a claim that this process independently verified historical bytes. API/manifest revision remains 3; runtimeRevision remains fetch-epoch-2. runtimeOptimization identifies the bookkeeping revision.

Invocation limits: max_candidates <=525312 covers both windows of 16 banks plus all crossing variants; artifact budget defaults to 192 MiB, maximum 256 MiB, covers aggregate writes and assembly. File default 1 MiB. max_ms <=25000 plus bounded input framing; Linux filesystem deadlines remain cooperative. Output default8192/max20480 bytes. All writes use exclusive descriptor-relative no-follow jobs beneath the existing safe work root. No overwrite, chmod, package install or network requests. Failure may leave confined partial jobs. Self-test uses bounded Node processes, removing NODE_OPTIONS/NODE_PATH, and only synthetic ROMs. Lower budgets may prevent completion. Tests included here have not been executed by drafting.

The MMC1 synthetic fixture places all vector-target RTI stubs in every physical PRG bank: selecting vector bytes in the high window must not accidentally require the same bank in the low window. Generic mapper policies do not contain game-specific behavior.

Performance revision snapshot-keys-1: built-in MMC1 snapshots use an explicit object literal, retaining the original field order and fresh mutable return value. Private state has exactly nine own data properties at initialization and restoration and is never exposed. banks1/ram1 calculations are unchanged. unchanged caches only the enumerable string keys of its private comparison snapshot and uses a counted loop. That fresh snapshot is never passed to a public callback, so its keys cannot change. This removes repeated private-object enumeration and a per-call closure. It does not cache public snapshots, trust wrappers, skip validation, or remove any callback or unchanged check. In particular getMapperState/getCPUClock may themselves mutate state, so apparently adjacent checks are retained. Arbitrary getter/proxy results retain valid1/spread behavior. Standard unmodified ECMAScript intrinsics are assumed as in the baseline; hostile intrinsic monkey-patching is not a sandbox boundary.

self_test adds differential mutations at every state/clock callback ordinal, snapshot isolation, and a fixed-work throughput smoke check. Its directory contains baseline-runtime.mjs, performance.mjs and performance-cases.json. After a successful self_test, run node performance.mjs performance-cases.json 6000 from that directory under an external 25-second process timeout. Work per sample is a multiple of six in6..60000; the script has a20-second cooperative deadline. It warms both implementations, alternates their order for five samples, and reports raw milliseconds and medians for direct and forwarding buses. Both use identical static translation tables, initialization and inputs; CPU/RAM/mapper/signals are compared. self_test uses60 steps/sample for smoke, not reliable speed evidence. No timing threshold controls correctness. This CPU microbenchmark does not establish browser frame performance. Drafting executes no tests or benchmarks.
