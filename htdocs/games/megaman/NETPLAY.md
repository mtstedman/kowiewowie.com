# Renewable shared-control netplay integration

This is an inert build-only package. It installs nothing, accesses no network and executes no game, compiler, browser or generated service. Source checkouts, generic references and original archives remain untouched. The builder preserves authenticated source inventories, replacement hashes, baseline dependencies and historical provenance.

## Independent lifetimes

Joined rooms have NO absolute session-age deadline. created_at is informational only. Unused invitations expire after 300 seconds and are consumed transactionally by one guest. Host and guest each use separate 256-bit random role credentials; the database stores SHA256 hashes. Maximum participants remain one host plus one guest. Guest recovery requires its existing credential and 15 seconds without an accepted guest poll, rotates the session and clears negotiation state. Exact join/rejoin retries retain join_id and return the same session. A consumed invite cannot admit another guest.

host_lease_until begins at 60 seconds. ONLY an authenticated accepted host poll renews it to database clock_timestamp()+60 seconds while the previous lease remains valid. Guest traffic, SDP, TURN credentials and invite age cannot renew it. A joined host can renew indefinitely, including while waiting for the same guest to return. Unused rooms still expire with their five-minute invite. Creation serializes admission, removes expired host leases and expired unused invites, and caps storage at 128 rooms. Two bounded SDP slots and fixed metadata per room replace history; 1024 fixed rate buckets and one gate cannot grow with anonymous traffic. Expired rows can remain while idle, but storage cardinality remains bounded without a scheduler.

Accepted role polls every two seconds update independent participant liveness. The opposite role is live for 15 seconds. Data-channel heartbeat silence over two seconds clears remote held state and queues, leaving host local input/game execution alone. Signaling failures disable remote input and retry; a single failed fetch does not revoke the room. Client authorization outage longer than 60 seconds stops local sharing and requires a fresh invite. This is a liveness boundary, not a gameplay age deadline. Background suspension longer than the lease is not guaranteed recoverable.

Stop Sharing closes local media/data, disconnects only the audio tap and tries authenticated room deletion three times. Confirmed deletion invalidates both roles and invite. Failed deletion is reported explicitly with the fallback of 60 seconds after the last accepted host poll. Deleted rows cannot be resurrected by in-flight requests. Issued TURN credentials and existing allocations are not instantaneously revoked by deleting signaling state.

## Matched API contract

Every endpoint is POST /api/v1/netplay/ACTION, same-origin HTTPS, Content-Type application/json and X-Netplay-Protocol: 2. Browser fetch uses credentials: omit. No query strings, CORS exception or cookie authorization. Origin must match https://Host and a configured origin; Sec-Fetch-Site must equal same-origin. All bodies include game (exact trailing-slash route) and artifact (generated binding digest). Responses are no-store JSON. Public errors are bounded fixed messages/codes, never exceptions, request bodies or SDP.

capabilities returns available, configured ICE URLs without credentials, iceTransportPolicy and reason. It checks configuration, not live reachability. create returns room (32 hex), credential (HOST ONLY, 64 hex), invite (64 hex), session empty, invite_ttl_seconds=300 and host_lease_seconds=60. Invite fragments contain only #netplay=ROOM.INVITE. Guest recovery data is saved before removing the fragment from history.

join takes room, invite, browser-generated guest credential and join_id (32 hex). rejoin takes room, that guest credential and a fresh join_id retained across retries. Both return session. The sole guest remains reserved to its credential. Make a new invite/room to admit someone else.

Role operations add room, credential, role and session. Host poll can present a previous session to discover guest recovery; guest operations require its current session. poll also sends round (last observed, empty initially) and recover ('none', 'restart', 'rebuild'). A guest recovery request is recorded only for the current round, fencing delayed recovery requests. poll returns session, round, mode, recover, peer_live, host_lease_seconds and message null or {round,description:{type,sdp}}. Polling continues independently of ICE/SDP work.

POST /api/v1/netplay/ice is the authenticated credential issuance AND refresh endpoint. It verifies role credential, current session and live host lease. Response is {available:true,iceServers:[optional STUN entry,{urls:[actual TURN URLs],username,credential}],iceTransportPolicy,server_time,expires_at,refresh_after_seconds}. Timestamps are Unix seconds from PHP. Username is decimal expires_at followed by ':' then 32-hex room then ':' then role. Credential is base64(binary HMAC-SHA1(username, literal backend shared-key string)). Coturn and PHP must use the same literal bytes, not a decoded interpretation of a hex string. The shared key never reaches the browser or this build tool.

Credentials last 600 seconds from issuance, independently of room creation time and the renewable 60-second host lease. One expiry timestamp per role is reused until at most 180 seconds remain; then a new 600-second window is issued. refresh_after_seconds is max(1,min(420,expires_at-server_time-180)). Clients schedule from monotonic request start, not browser wall-clock time. The guest also requests host-coordinated renewal when its own refresh deadline arrives.

Only host calls begin with previous=current round, round=new random 128-bit ID, mode=restart or rebuild. Room lock plus compare-and-swap reject superseded requests. Exact retries of the current ID/mode are idempotent; minimum eight seconds between new rounds. begin replaces both SDP slots and clears recovery state. Only host can signal an offer and only guest can signal an answer after the offer. signal includes round and description, capped at 32768 bytes and 64 candidates. Each slot is immutable within its round; exact retries are allowed. No growing sequence history or absolute session counter exists.

## Refresh and recovery

A renewal starts before TURN admission credentials expire. Each endpoint fetches its own credentials, updates ICE configuration while preserving immutable PeerConnection fields, and participates in one host-owned offer/answer exchange. Host calls restartIce and createOffer with iceRestart when a prior description exists, verifies changed offered ICE ufrags, gathers bounded non-trickle candidates and signals. Guest updates configuration BEFORE applying the offer and creating its answer. Polls remain independent so negotiation cannot starve host authorization. Lost signal responses retry identical cached SDP no faster than every two seconds. Sessions, random rounds and local revision checks fence stale callbacks.

setConfiguration alone does NOT refresh existing TURN allocations. W3C/JSEP applies changed servers to the next gathering phase. RFC 8656 requires subsequent allocation requests to retain the original username; browsers manage allocation Refresh, permissions and channel maintenance. Coturn documents that established allocation session credentials can persist beyond the REST admission timestamp. max-allocate-lifetime=600 limits one allocation refresh interval, not cumulative gameplay lifetime. New credentials support new allocations during subsequent gathering/restart; browser allocation reuse and selected-pair behavior require observation. Changed ICE ufrags and a live data channel do not prove that every selected allocation obtained a new TURN username.

Initial negotiation receives its bounded 45-second attempt window without mistaking the absence of an initial data heartbeat for a disconnect. Completed healthy connections have no age cutoff. Credential/SDP/restart failures visibly release remote inputs and retry; Retry connection is available in both roles. An ordinary restart keeps the existing healthy PeerConnection/media path. Failed or closed transports can trigger a coordinated rebuild with fresh credentials and the same game canvas/audio source. A timed-out native WebRTC operation cannot be cancelled, so its connection is closed before reuse and recovery requests rebuild. At most one connection exists per role. Rebuild can cause a media gap; it never resets the host game/worker or clears host local controller state. No seamless-media claim is made.

Input uses reliable ordered DataChannel romjs-input-v2, full eight-boolean state, guest session, random release epoch, increasing sequence and a fresh random host challenge. Pulses are every 250ms; accepted challenges are younger than one second. A barrier clears remote queues and requires a fresh all-released state. Guest blur/hidden sends a release flag with its authenticated input identity, clearing remote queues as well as held buttons. Host pause/blur/hidden retain original local lifecycle behavior and establish remote barriers. Sequence is reset under a new epoch before exhaustion rather than terminating a long game. Sender cap 120 states/second plus burst 120, receiver cap 240/second, payload 1024 characters, bufferedAmount 16384. Independent local/remote 32-edge-per-button SampledInput queues are ORed at the original host frame sample. Malformed/overflowing remote traffic stops sharing without modifying local input. Already dispatched frames cannot be undone.

## Separate provisioning owner

The FOLLOWING tool-builder task owns actual coturn installation, managed service, firewall, TLS and protected backend environment. This build emits an inert example only. Operator-supplied facts: turnserver absent, no TURN service/listeners; wowiekowie.com resolves to 104.194.11.114; TLS material under /etc/letsencrypt/live/wowiekowie.com; PHP-FPM8.5. These facts were not live-tested by this draft. No credentials, alternate hostname, NAT topology, firewall state or certificate permissions are assumed.

Protected /etc/wowiekowie.com/api.env uses the existing INI parser. Required environment names: WOWIE_NETPLAY_ENABLED (false until verified), WOWIE_NETPLAY_ORIGINS (comma-separated exact HTTPS origins), WOWIE_NETPLAYPLAY_TURN_URLS (1..6 comma-separated real turn/turns URLs with explicit ports), WOWIE_NETPLAY_TURN_SECRET (32..256 characters; preferably a 64-character hex encoding of 32 random bytes, used literally). Optional WOWIE_NETPLAY_STUN_URLS (0..2 URLs) and WOWIE_NETPLAY_ICE_POLICY ('all' default, 'relay' for forced-relay observation). Existing WOWIE_DB_DSN/USER/PASSWORD remain managed by the backend owner. WOWIE_ENV_FILE and existing process variables take precedence in Config; verify effective configuration without printing private values. No secrets are packager inputs or embedded defaults.

If the provisioning owner verifies use of the existing hostname/certificate, matching URLs can be turn:wowiekowie.com:3478?transport=udp,turn:wowiekowie.com:3478?transport=tcp,turns:wowiekowie.com:5349?transport=tcp. These are a proposed contract, not deployed-listener evidence. Coturn requires use-auth-secret, ':' REST separator, protected static-auth-secret directive matching the literal backend value, stable verified realm, actual listening/relay addresses and valid certificate/key with managed permissions/renewal. No static browser accounts or unauthenticated relay. Keep clocks synchronized. Keep nginx's 443 socket.

Allow UDP/TCP 3478, TCP TLS 5349 and UDP relay ports 49160-49259; UDP relay endpoints remain necessary for TCP/TLS clients. NAT requires verified port-preserving mapping. Do not advertise unreachable IPv6. Use a supported patched coturn version and verify template options. Template quotas are user-quota=8, total-quota=256, max-bps=500000, bps-capacity=20000000, max-allocate-timeout=30, max-allocate-lifetime=600 and stale-nonce=600. The 100-port range and bandwidth caps can admit fewer rooms than the signaling cap; measure capacity. Preserve protocol-default permission/channel lifetimes.

Deny private/link-local/metadata/loopback/multicast and operator service egress, while allowing intended relay-to-relay traffic. A blanket denial of this relay's public address can break two participants using the same relay; the provisioning owner must apply suitable port/service restrictions. No admin listener, server-relay or verbose credential/body logging. Review WAF/proxy/FPM/APM/coturn logs. REST expiry does not force termination of malicious established allocations; immediate relay revocation requires separate relay administration.

## Preserved runtime and publisher ownership

Guest mode imports no game worker, machine or ROM. Only host runs the original game. Canvas capture streams the displayed 256x240 image. Actual game AudioContext master gain branches into MediaStreamDestination while retaining its original local destination. No microphone, camera, chat, invented PCM, pitch change or scheduling change. Guest receives one media stream and draws without smoothing at existing integer 2x/4x scale. Late audio uses replaceTrack; incompatibility requests a coordinated rebuild. Keyboard, standard gamepad and multitouch retain generic aggregation/release. Offline play remains available without signaling/TURN. Autoplay gestures, compression, latency and browser scheduling remain limitations.

Runtime/machine/ROM/cartridge/bank/device/dependency bytes remain unchanged. Original pinned app/worker/controller integration is required. Historical compiler/bundler evidence remains explicitly historical. Current runtime-files, bundle-inputs and manifest inventories describe emitted bytes. Manifest drift requires an independently trusted complete inventory. Unsupported older UI contracts fail with expected/actual hashes. No full conversion, speed or game correctness claim is added.

The other parent owns update publication. Outer romjs-netplay-integration/1 and romjs-netplay-integration-bundle/1 authentication/allowlist contracts remain. Protocol 2 and changed browser bindings require matched browser/backend publication. Initial UNPUBLISHED netplay SQL now uses invite_expires_at, host_lease_until, random rounds and two TURN expiry fields instead of absolute expires_at and capped SDP cursors. The packager refuses an existing NetplayService.php or netplay-games.json. If old netplay SQL was already deployed, author a separately reviewed additive migration; never alter applied migration history. VERSION, chain checksum and SCHEMA marker/pin/history are generated together against the trusted site baseline.

Existing new-route-only romjs-site-publish remains unchanged and incompatible with these updates. The separate update publisher must authenticate outer manifest, integration.json, source links/inventories, expected commit, every prior hash/absence, replacement length/hash and exact allowlist. Refuse affected uncommitted work and drift. Stage an isolated checkout preserving unrelated/untracked files, archives and references. No reset, clean, stash, force-push or broad staging. Publish enumerated bytes through normal fast-forward release and migration-before-application flow. Nginx installation requires live prior-byte checks, durable backup, nginx -t, reload and rollback receipts. This packager does none of it.

CSP remains unchanged, including camera/microphone denial; MediaStream srcObject uses a local provider. No wildcard/eval/inline expansion. Nginx replacements implement bounded same-origin short polling without access logs and deny separate-API-origin netplay. Long games use short HTTP requests, not long-lived PHP processes. Rate bounds remain 300 requests/second and 30 creates/minute globally, 600 requests/minute and 6 creates/10 minutes per fixed bucket, 100 requests/minute per role; statement/lock limits are 1000/250ms.
