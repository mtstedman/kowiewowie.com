## Authority and recovery

Protocol 3 uses same-origin HTTPS POST JSON with X-Netplay-Protocol: 3, credentials omitted, and no cookies, Authorization or query signaling. Every operation is package/artifact/binding scoped. Each room admits four watchers and one player, including pending invitations. Participants have immutable roles/players, domain-separated credential hashes, five-minute single-use invitations, independent sessions/heartbeats/rounds/SDP slots and TURN lifetimes.

Host polls renew a 60-second host lease; joined sessions have no fixed age cutoff. Participant liveness is 15 seconds; idle cleanup is 300 seconds. Play data silence releases held input after two seconds. Background suspension can exceed these limits. Watchers have input=false/player=null. Browser/backend SDP validation permits audio/video only for watchers, with sendonly offers and recvonly answers; application/SCTP sections and unsolicited data channels are rejected. Watcher input methods/parsers reject input. No server input or role-upgrade endpoint exists.

Play uses reliable ordered game-input-v3, room/package/artifact/participant/player/descriptor/session binding, random epochs, fresh challenges, monotonic sequence numbers, all-released arming and revision fences. Quick taps remain frame-sampled. Overflow releases remote input. An already dispatched frame cannot be undone. Rejoin requires prior inactivity, rotates sessions and preserves response-loss idempotence through join_id. Private resume records must not enter telemetry.

Revocation first blocks local readmission and closes only the affected participant. An unconfirmed revoke ends sharing locally and attempts room deletion. End closes peers/capture/input queues and retries bounded server revocation, returning confirmation separately. Page exit may interrupt requests; lease expiry remains necessary. Received media and existing TURN allocations cannot be instantly retracted.

Limits remain 32 rooms, five participants each, ten replaceable SDP slots, 32768 bytes/64 candidates/1024 lines per SDP, 1024-byte SDP lines, 450000-byte serialized room state and a 524288-byte PostgreSQL bound. Data packets are limited to 8192 characters. Existing 1024 IP buckets/global rates remain; per-bucket traffic rises to 1200/minute, creates stay 6/10 minutes. Host traffic caps at 400/minute and guest at 100/minute. Polls are at least 300 ms apart; new rounds at least eight seconds apart. SQL statement/lock bounds are 1000/250 ms. These limits do not establish measured media capacity.

TURN credentials last 600 seconds and refresh within 420 seconds from request start. Usernames bind room/participant/session/side. The host coordinates negotiation; guests request current-round recovery. Both update ICE configuration, restart healthy peers and rebuild stalled connections individually. setConfiguration is not renewal by itself, and ICE restart does not prove a new TURN allocation. Multiple real browser/relay cycles still need observation.
