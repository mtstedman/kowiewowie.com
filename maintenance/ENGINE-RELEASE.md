Engine maintenance CLI (Node ES modules)

The exact executing assembler ships as maintenance/romjs-shared-engine-release-assembler.mjs in each fresh output site. It requires authenticated Acorn 8.17.0 dist/acorn.mjs supplied separately. No network or secrets are used.

Run: node maintenance/romjs-shared-engine-release-assembler.mjs < /external/release-input.json

Input JSON fields: root (current emitted modular site), output_directory (fresh disjoint directory), source_inventory (external JSON file), source_inventory_sha256, acorn_module, acorn_sha256, release (increasing stable same-major semver), edits ([{path,before_sha256,file,sha256}]). Optional admissions accepts [{root,sha256}] for fresh nes-engine-admission/1 bundles, authenticating all new engine/cartridge members and recording catalog changes in successor history. Admission does not establish gameplay qualification. Optional binding_repairs accepts caller-pinned [{path,sha256}] nes-network-binding-repair/1 records for existing inactive packages whose earlier admission emitted an incomplete network binding. A repair forbids runtime/package mutations but may accompany strictly scoped test/maintenance support edits, preserves package identity and roles, and must pass the production generic NES binding schema before immutable catalog/PHP/history refresh. Perform this repair in a successor before qualification. Optional qualifications accepts caller-pinned [{path,sha256}] nes-package-qualification/1 records for an existing inactive package with an already valid production binding. Qualification forbids runtime/package mutations and combination with repair, but may accompany strictly scoped test/maintenance support edits; it authenticates eight package-bound evidence reports and changes only capabilities.verified/evidence before normal immutable digest, binding, pin and history refresh. It is an operator review attestation, not a cryptographic attestation or automatic correctness oracle. Optional support_additions adds pinned new tests/maintenance .mjs files under the same path restrictions. Optional support_edits can also update package.json scripts while preserving dependencies and other fields. Optional support_edits uses pinned edits for existing tests/maintenance .mjs files (excluding history and this assembler, which is copied from the executing source). Optional shell_additions accepts [{path,file,sha256}] for new /games/arcade/*.mjs modules reachable from the final authenticated package graphs. Optional shell_edits uses the same edit schema for existing executable package members outside cartridge and engine trees, plus the authenticated loader. Shell changes are validated before mutation and included in package graphs, bindings and immutable history. All SHA256 values must be independently trusted lowercase hex. An edit path is the CURRENT /games/engines/nes/<release>/common/<hash>.mjs or composer.mjs URL; file is the external edited source file. Never use the pre-extraction baseline.

Inventory format: {"format":"nes-release-source/1","files":{"relative/path":{"bytes":123,"sha256":"<trusted SHA256>"}}}. Cover every regular source file exactly, including maintenance scripts and history. Regenerate and authenticate this inventory before EACH release; do not reuse an earlier inventory. Supply a fresh output path for every run.

Stdout is one JSON receipt containing output_directory, release, receipt path, changed/added/preserved counts and executed_tests. Errors go to stderr with nonzero exit. A failed output write may leave a partial fresh directory. Inputs are never written; output is never deployed or activated.

The output refreshes current audit/runtime source pins and authenticates immutable successor history before the original shared-engine migration verifier runs. Historical receipts are retained; maintenance head and history wrapper are current pointers. No cryptographic signature is minted: trust comes from caller inventory SHA256 and embedded receipt hashes.

Later explicit regression: node tests/engine-release-<release>.mjs maintenance/romjs-shared-engine-release-assembler.mjs /external/release-input.json

Temporary fixtures remain available for inspection. Drafting does not execute these checks. Browser/PHP/deployment tests remain separate gates.
